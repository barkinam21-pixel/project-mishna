# P07 production bridge (2026-11-15)

This extends the existing M3 coordinator, signed gateway, P07 three-reference multipart compiler and pinned private Drive process. It never invokes the older Horde-capable image Worker. The existing public Actions generation path remains blocked; it must not carry private art. No new service or AI binding is required for this source change.

## Executable path

`python -m tools.m3_production_runner --root <owner-workspace> --private-draft <private-json> --request-id <32hex>` is the default zero-network compilation/dry-run. It checks exact original reference hashes using #114 and reports hashes only.

On an existing **owner-private host**, append `--once --history <private-history-json> --legacy-runtime <pinned-checkout> --state-id <existing-id> --snapshot-id <existing-id>` to execute the one-shot chain. Existing host environment supplies `M3_GATEWAY_URL`, `M3_GATEWAY_HMAC_KEY`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, `MISHNAH_DRIVE_OAUTH_JSON`; none go in command arguments or logs. These are operator/service instructions, not a request for Bar to run commands. The host first verifies private Drive access and unchanged source history/snapshot; it then calls signed bootstrap/reserve, makes one exact Cloudflare4B POST, fsyncs original response bytes, decodes/validates 1024×576, preserves original plus derived PNG, records receipt, preserves all old Studio snapshot members, updates the existing private snapshot/journal and verifies download hashes. The reference archive is not modified. No new Drive files/ACLs are created.

`--resume-delivery` with root/request-ID/pinned runtime/state/snapshot arguments requires neither draft nor reference images nor provider credentials. It reconciles saved bytes and repeats only storage operations. No provider object enters that function. If reservation or POST response is lost before bytes were saved, the attempt remains `SUBMISSION_UNCERTAIN_NO_RETRY`; there is no release/reset endpoint or automatic retry. Read signed status instead. Human inspection remains required for visual/artistic quality; candidates always `accepted=false`.

## Production scope is CLOSED by default

The production HTTP route is `/m3/v1/production`, separately HMAC path-bound and restricted to ACT1-PROLOGUE. It uses a different deterministic object name in the **same existing namespace**, preserving the commissioned synthetic canary singleton. Existing offline methods cannot mint production permits. `production-ledger.mjs` contains no network/model calls.

Dispatch requires a separately reviewed, protected deployment setting `M3_PRODUCTION_CONFIG`, not an HTTP-provided authorization flag. Its exact schema is checked in `config()`: version1, scene ACT1-PROLOGUE, shot EP-P07, exact new request ID, original history bytes SHA256, exact compiler body/draft/reference hashes, baseline6, total7/max1/$0, current expiry within five minutes, and affirmative owner/synthesis-rights/privacy/Free-hard-stop/quota/private-storage/legacy-writer-fence evidence. This setting must be prepared from real private artifacts and approvals by the existing trusted owner host; **unit-test fixtures are not commissioning evidence**. No setting was created by this work. A successful reserve permanently consumes the singleton; changing a setting never resets the baseline/attempt. One-shot limitation is intentional for this milestone, not a finished N-shot scene queue.

Immutable baseline stores exact full six-attempt JSON and SHA, including old candidates and unknown fields. Admission cannot substitute a synthetic count6. Protected hash/provenance and actual legacy-writer exclusion must be commissioned before setting `legacy_writers_fenced=true`; neither SQLite nor a client boolean prevents external legacy writers on its own. The unchanged old Issue runtime still rejects production; remaining out-of-band owner tools must be reconciled at commissioning.

Receipt/delivery reconciliation is allowed after dispatch scope expires, is token-bound and immutable, and never grants dispatch again. The production attempt is recorded once in SQLite before POST; Drive is a verified delivery mirror, not CAS or authoritative concurrency control. Exported attempt representation stays stable after delivery so repeated uploads cannot alter its hash. Existing snapshot entries are hash-verified/preserved and mismatched replacements block. An orphan response lost before fsync remains unrecoverable automatically; it requires review, never a second inference.
