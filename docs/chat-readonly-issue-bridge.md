## למה המסלול הזה

במלאי הכלים הזמין קיים replay-job ו־update_issue, אך לא workflow_dispatch או repository_dispatch. fetch מוגבל ל־GET; אין להשתמש בו כאילו הוא POST. חיפוש מחברים מצא את חיבור GitHub שכבר מותקן, ללא כלי dispatch חלופי מתאים שניתן להפעיל כעת. מחברי Cloudflare המחוברים מוגבלים ל־Cloudflare API, ולכן אינם מסלול לאחזור/ייצוא token GitHub או עקיפה שלו.

[GitHub מתעד](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#issues) אירוע `issues.edited`, אך הוא מחייב שה־Workflow יימצא בענף הראשי. זו חסימת ההפעלה האמיתית שנותרה, ולא בעיית OAuth או התקנה במחשב. תיעוד [OpenAI](https://developers.openai.com/chatgpt) מתאר כלים מחוברים בעלי יכולות קריאה וכתיבה; הוא אינו מוכיח שכל כלי שמוצג ב־Work מוצג גם בשיחה רגילה של החשבון. עדכון Issue הוא המסלול המתאים בשיחה שחיבור GitHub שלה מציג את פעולת העדכון. אין צורך להפעיל Python, דפדפן או תוכנה אצל בר.

## אופן ההפעלה לאחר אישור מיזוג הגשר בלבד

1. הסוכן קורא את Issue54 בגרסתו הנוכחית, את הוראות הגשר ואת מצב ה־Workflow, ומוודא שהגשר זמין בענף הראשי. אין לשלוח בקשה לתשתית שעדיין לא מותקנת.
2. לבקשת בדיקת החיבור/הכנת OPN02, הסוכן משאיר את ההיסטוריה ומוסיף/מחליף רק בלוק JSON קטן בשם `mishnah-readonly-request`: version1, request_id בן32תווים הקסדצימליים חדשים, operation מתוך רשימת שתי הפעולות, ו־issued_at ב־UTC. `tools/chat_issue_bridge.py:make_request` הוא המימוש הדטרמיניסטי של פורמט זה; השיחה יכולה להשתמש ישירות ב־update_issue בלי סביבת Work.
3. הסוכן מעדכן את Issue54 דרך הכלי המחובר. אין לשים secret, כתובת הורדה חתומה, מדיה, command, נתיב קובץ פרטי, מזהי גישת Drive חדשים או payload של מודל בגוף הבקשה.
4. הגשר מאמת את אירוע העריכה. רק אחרי אימות משתחררת משימת בדיקת Drive בעלת Secret קיים יחיד. הקוד הקבוע בוחר את שלושת הקבצים הקיימים מתצורתו; הבקשה אינה יכולה לשנות SHA, repo, קובץ או endpoint.
5. הסוכן מאתר את ההרצה החדשה מסוג issues ובודק jobs/logs. קבלה של עדכון Issue אינה הוכחת ביצוע. רק תוצאת `prepare-opn02` עם שלושה קלטים, source/layout תקינים, 0כתיבות/0יצירה ו־generation_authorized=false היא ההוכחה החיה המבוקשת.

אין צורך לייצר מחדש OAuth, להתקין כלי, לשנות permissions או להחליף את ה־snapshot. אין למפות בקשות כגון ״תכין סרטון״, ״תקן דמות״, ״תגבה״, ״מזג״ או ״צור תמונה״ לאחת מפעולות ההפעלה כדי לעקוף אישור. ״תמשיך את המשנה״ מתחיל מקריאת מצב הפרויקט ומוביל לבדיקה רק אם היא נדרשת.

## הגנות

- repo קבוע, Issue54 פתוח בלבד, פעולה edited בלבד, sender שהוא בעל המאגר בלבד; PRים, חשבון אחר ומספר Issue אחר חסומים.
- parser בספרייה התקנית, JSON bounded, שדות/גרסה/operation סגורים, דחיית מפתחות כפולים ויותר מבלוק אחד. גוף Issue לעולם אינו מוכנס ל־shell.
- request_id חדש ועריכת גוף אמיתית נדרשים. עדכון תיעוד ללא שינוי request_id אינו מריץ שוב את הבדיקה. timestamp ב־UTC עם חלון15דקות וסטייה קדימה עד60שניות. זה אינו ledger מבוזר של exactly-once; בעלים יכול לשלוח מזהה חדש כדי לבצע עוד בדיקת קריאה.
- validation ללא secrets; runtime רק לאחר פלט operation תקין, owner gate וקוד immutable. `contents: read` בלבד. PR CI אינו מקבל Secrets. אין artifact מדיה, אין Cloudflare token, אין ענף ריצה לבחירת המשתמש ואין מצב `run`.
- השחזור משתמש בספריות זמניות ונמחק מקומית. השגיאות/פלט מכילים קודים ו־hashes בלבד. אין תגובת Issue אוטומטית עם תוכן פרטי.

## מה נשאר מחוץ להוכחה

ה־runtime עדיין כפוף לשערי מקור/זכויות/קול/סגנון/מכסה ואישור ניסיון חדש. היעד25–35%גובה וכפר שאינו מצודה לא נפתר על ידי חיבור גשר. אין סרט או מדיה חדשה. בלי מיזוג חד־פעמי של הגשר אי אפשר להוכיח live3inputs באמצעות כלי המחבר הנוכחיים: replay הקיים נשאר קבוע בקוד הישן. אחרי המיזוג המורשה ניתן לשלוח ולבדוק את הבקשה מכאן בלי פעולה ידנית של בר, ואז לבדוק בנפרד את זמינות הכלים בשיחה רגילה.
