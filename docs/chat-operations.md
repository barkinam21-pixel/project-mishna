# הפעלה מתוך שיחה — מסלול ראשוני מוכח

## מה עובד עכשיו

ב־13.11 הופעלה דרך כלי GitHub המחובר **הרצה חוזרת של בדיקת Drive קיימת ומאומתת**. הבקשה התקבלה והסתיימה בהצלחה: [run43337618166, ניסיון2](https://github.com/barkinam21-pixel/project-mishna/actions/runs/43337618166/attempts/2), job131608506464. היומן מחזיר `DRIVE_RESTORE_AND_LOCAL_PREFLIGHT_VERIFIED`, אפס inference, אפס כתיבות ו־generation_authorized=false. לא נפתח דפדפן ולא נדרשו פקודה/CLI/סוד מהבעלים. [ראיה](evidence/chat-readonly-activation-2026-11-13.json).

הפעולה בוצעה מתוך סביבת Work, אך דרך **המחבר בלבד**; אין לטעון שנבדקה שיחה רגילה נפרדת. היא ניתנת להפעלה בלי Work רק בשיחה שמציגה את אותם כלי GitHub. אם כלי ההרצה אינו זמין שם, יש לדווח על כך ולא להבטיח הפעלה או לבקש מהבעלים לפתוח כפתורים שלא לצורך. אין שרת חדש, אפליקציה חדשה, חשבון חדש, API ציבורי או token מועתק.

## הוראות לסוכן בשיחה רגילה

1. קרא את מצב הפרויקט ב־Issue54 ואת ההוראות הללו בענף הפעיל של PR57. בדוק אם כבר קיימת ראיית הצלחה טרייה; אין צורך להפעיל שוב בדיקה רק משום שהתחלפה שיחה.
2. בדוק שקיימים `github_fetch`, `github_fetch_file`, `github_fetch_workflow_run_jobs`, `github_rerun_workflow_job` ו־`github_fetch_workflow_job_logs`. אין להשתמש ב־fetch ל־POST ואין להמציא כלי dispatch שאינו מוצג.
3. קרא את run43337618166 ואת קובץ `.github/workflows/verify-private-drive-readonly.yml` ב־SHA `4b14becd05c5ce6690800a545a3e620850fe45e4`, ואת רשימת jobs העדכנית. בדוק repository/owner, אירוע workflow_dispatch, path מדויק, SHA מדויק, תוכן workflow blob `162d2698e20b296ee23c0e3cc2a2eddfdd65fa07`, job יחיד `drive-readonly`, run שהסתיים וחלון פחות מ־30 יום. קובץ זה בוחר בקוד הריצה **הקבוע** `2a7544d7d63a4e90e0872ba31df9736cd3103a21`. אין להחליפו בענף נע.
4. רק אחרי התאמה מלאה, הפעל `github_rerun_workflow_job` עם repo_full_name הקבוע ו־job_id החדש שהוחזר מהרשימה. אל תשמור job_id ישן כיעד קבוע; הוא משתנה בכל ניסיון. אין להריץ workflow אחר או job עם תלויות נוספות.
5. קרא את metadata/jobs/logs עד לסיום או לחסם. הצלחת בקשת ההפעלה בלבד אינה הצלחת בדיקה. דרוש ניסיון run חדש, conclusion=success, סטטוס האימות המדויק וערכי 0 כתיבות/0 יצירה/false באישור. שמור קישור וראיה ללא סודות, prompts או קלטים פרטיים.

`tools/chat_operations.py` מממש את בדיקות ה־allowlist ותוצאת ההפעלה כקוד מקומי ניתן לבדיקה. הוא אינו מבצע קריאות רשת, אינו מפעיל shell ואינו מעתיק credentials. בשיחה רגילה הסוכן מבצע את אותן בדיקות על תוצאות הכלים; אין דרישה להריץ Python אצל בר.

## מגבלות אמיתיות והמשך

GitHub מאפשר replay עד30יום מההרצה המקורית, ובאותו SHA/ref. זה מסלול ראשוני מוכח, **לא פתרון הפעלה נצחי**. אחרי החלון דרוש bootstrap של הרצה בטוחה חדשה או כלי workflow_dispatch מתאים. הוא אינו מוצג בחיבור הנוכחי; לא הוספנו webhook ציבורי כדי לעקוף זאת. מקור: [תיעוד GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs).

הריצה המוכחת משתמשת בקוד2a7544d וב־snapshot המרוחק הישן. היא אינה מפעילה את קוד PR57 החדש או מוכיחה שלושה ייחוסים מרוחקים. עותק השחזור המאוחד נבדק ונשמר בנפרד אך **לא הותקן על ה־snapshot המחובר**. אין למזג PR53/57 או לשנות reviewed SHA/Secrets כחלק מבקשת check.

השלב הבא: אישור ממוקד לעדכון snapshot קיים בעותק שנבדק, תוך שמירת הנכסים והגרסאות הישנים; בנפרד, סקירת קוד/מיזוג רק באישור הבעלים. אחר כך בדיקת3הייחוסים בקוד מאושר, ולבסוף אישור חדש לניסיון יחיד. יצירת תמונה/קריינות/סרט נותרת חסומה ולא מובטחת על סמך הפעלת check.
