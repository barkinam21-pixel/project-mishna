## B. Professional film continuity engine — single source of truth
Implement immutable/versioned **scene manifest** and **production bible**:
- `episode > act > sequence > scene > beat > shot`: each with stable ID, script version/hash, source layer and confidence, dramatic intent, preceding/following shot, shot length in integer frames, continuity state and sound cue timing.
- **Character DNA**: reference image hash, design/face sheet, age range, proportions, eye/hair/beard, costumes layers/colors and changes, props and which hand holds them, motion/weight/posture, emotional state; in/out state for scenes.
- **Location & camera DNA**: location and era, layout/map, entrances/exits, geography and 180-degree action axis, screen direction, eyeline, character left/right order, lens feel/height/scale, blocking and depth, sun direction and position, time of day, weather, colors/texture/artstyle. Consistent eras, no accidental daylight jump.
- **Story state and chronology**: what has already happened, what a character knows and intends, how a dramatic beat changes state, referenced source/interpretation, when one time period ends and another begins; hard check 70 CE / Tannaim in act 4, Rabbi/redaction ~200 CE in act 5. Sinai is traditional symbolic imagery; reconstructed exact site/portrait and invented meetings must never be presented as documented fact.
- **Dialogue/narrator state**: exact approved text and attribution, speaker, Hebrew display/spoken/pronunciation field, pronunciation dictionary, voice identity/pace/style, date of review, explicit creative dramatization tags.
- **Music & sound state**: original licensed motif IDs, location ambience, Foley, SFX, spatial depth, L/J-cut anchors, silence, changing emotional intensity; no sudden music or background discontinuity unless directed.
- **Visual asset origin**: original generated image, derivative crop, repaired image, cached accepted asset, mock/placeholder, or human art. Never label an unreviewed candidate as accepted, and never use image content as proof of history. Current OPN02/03 `accepted=false`.
- **State changes**: each shot declares pre-state and post-state, and explicit continuity exceptions (time jump, axis-cross, weather change, montage) with a deliberate transition. Compare previous shot's post-state against next pre-state and block unexplained mismatch.

### Pre-generation shot contract
Every shot must have `why` (what new information/emotion/camera meaning), `literary_script_span` + `version_hash`, `shot_description`, composition, blocking, camera, scale, set, character locks, sound entry/exit, cut reason, previous/next relation, desired narration/captions and max cost. Reject a shot with no story function. **Many meaningful shots, not repeated AI stills or generic zooms**. Use 4–7+ original images for dramatically dense scene packs as warranted; 15 edited shots do NOT mean 15 model requests or unlimited image generation.

## C. Real no-hassle automation and failure semantics
- One command from chat: `scene produce --scene ACT1-PROLOGUE --script-lock <hash> --max-inference <N> --budget-usd 0` (illustrative API only, implement documented exact syntax). **One owner approval scopes a precise scene/spec hash + bounded number of attempts + zero/preset spend; authorization is not a blanket renewal.**
- Build `scene plan / dry-run / status / assemble / produce` with machine-readable output and concise Hebrew status; one action for owner, one private viewing link to completed scene, one review. No screenshots, shell commands, manual editing or clip management by Bar.
- Durable append-only ledger + transactional job state machine: `PLANNED -> SCRIPT_LOCKED -> PREFLIGHT_READY -> AUTHORIZED -> GENERATING -> ASSEMBLING -> TECH_QA -> CREATIVE_QA -> OWNER_REVIEW -> ACCEPTED`; `BLOCKED/FAILED/INFERENCE_UNCERTAIN` terminal holds require investigation. Never call a model for plan/dry-run/status.
- **Idempotency** by owner request ID + scene ID + script/visual spec hash + backend; duplicate action never leads to duplicate paid inference. Save reservation **before** external inference, and record receipt/response and private storage after; if provider times out after possible submission, set `INFERENCE_UNCERTAIN_NO_RETRY`; do not infer "failed so retry" from a network error. If storage fails after inference, preserve journal state and recover original output without a new image charge.
- Serialize per-scene writer and globally coordinate shared quota/Drive journal; inspect live account quota & Free hard cap immediately before dispatch. GitHub Actions `cancel-in-progress:false` **alone does not guarantee all waiting requests survive**: official docs describe default one-pending replacement, and optional `queue:max`. Research and test actual queue semantics; also use durable request queue/locks so cancellation cannot trigger duplicate production.
- Use checkpoints and immutable hashes for each completed stage, fast incremental re-render and reusable approved caches; separate `asset_key` from `build_key`. A subtitle change must not re-generate images, a face change invalidates affected frames only; never reuse rejected/candidate images silently. Preserve originals, hashes, assets, logs, and source text privately; GitHub gets code/manifests only.
- Error handling: one stable reason code and actionable internal diagnostic, no secrets/sensitive provider responses in public logs; partial result explicitly `NEEDS_REVIEW`/ `BLOCKED`, never `COMPLETE`. Let non-inference steps retry with bounds; no endless loops or manual work for owner.
- Performance: benchmark planning, inference, audio, rendering and upload separately. Prefer batch operations/parallel **independent** tasks while preserving story and quota serialization. Cache successes, cap memory/runtime, avoid unbounded long jobs. Optimize after correctness; report true latency metrics rather than promising instant 35-minute films.

## D. Automated tests **AND** human creative checks — no false green
### Programmatic hard gates (CI with mock provider + fake Drive, no charges)
1. Wrong scene order, act/era/source attribution, one era passed off as another, and known dawn↔sunset contradiction fail preflight unless explicit scripted time transition.
2. Face/wardrobe/prop/matching scene IDs, left/right screen direction, 180° camera axis, eyeline and shot adjacency assertions are attached to manifest; no accidental shot swap/dropped/repeated shot; verify correct image bytes match the expected SHA.
3. Voice clip selection and pronunciation/wording are bound to the approved script; subtitle text derives from exact approved master, right-to-left UTF-8 NFC, grammatical wrap, safe margins and readable speed. Disallow phantom words, invented lines, source quote changes.
4. Foley and music stems actually exist and align to shots in 48kHz **samples**, dialogue ducking/peaks/loudness checked, meaningful silence preserved, no fake sound track. File existence != successful listening.
5. FFmpeg/ffprobe checks: 24fps, integer frame count, 16:9 (known actual dimensions), H.264 yuv420p BT.709, audio AAC 48kHz stereo, Hebrew language tags, decode full output, detect black/frozen frames and unexpected silence. Validate MP4 duration against manifest within frame/sample tolerance.
6. Timing tests for motion/cut transitions: no unplanned frame gaps, no unintended repeated still for > specified hold, correct shot start/end, L/J cut audio alignment. Match-cut/axis crossing exceptions explicit and reviewed.
7. Auth/free cap/zero spend fails closed; simulate ambiguous POST, race/double issue edit, canceled pending GitHub run, lost Drive snapshot, partially returned image, crash before/after reservation, wrong script hash, two concurrent workers; **assert at most one possible provider submit for any exact authorized ticket**, no loss of past 6 journal attempts.
8. Full dry-run with actual prologue plan and synthetic/placeholder scene (no real model), plus **MP4 playback review**. Tests prove the engine produces a valid technical render; do not label as visually completed.
9. Reproducibility fixture: same immutable inputs result in same shot/order/frame count/captions and asset selection; encoder binary bitwise output may vary by environment, so separately track reproducibility environment and hashes without promising byte identity across FFmpeg versions.
10. Attack/abuse tests: owner-only issue events, issue-body prompt injection, forged metadata, invalid licenses, path traversal, oversized refs, missing files, secrets in logs, accidental public artifact upload, workflow triggered from wrong branch/ref.

### Human-assisted, evidence-based review; not automatable certainty
- Frame contact sheet and side-by-side adjacent-shot comparison of face anatomy, fingers/hands, hair/beard, clothing, straps/props, same sun direction/day/night, background, architectural period and unwanted AI text; report uncertain cases for human review rather than claiming AI confidence == fact.
- Narrative and visual review of every **scene**, not each shot approval: visual clarity without audio, audio-only intelligibility and natural acting, continuity watch, first-time viewer comprehension. Source expert/Torah review **before final/public release**.
- Distinguish `TECH_PASS`, `SOURCE_REVIEW_PENDING`, `CREATIVE_REVIEW_PENDING`, `OWNER_APPROVAL_PENDING`, `READY_PRIVATE_PREVIEW`, `FINAL_RELEASE_APPROVED` with different documented conditions; **no "100% error-free" promise**.
- Generate QA report with test names, check time, tool versions, evidence (probes + contact sheets + private link), actual skipped tests and issues by severity. No pretending green unit tests means final film approval.
